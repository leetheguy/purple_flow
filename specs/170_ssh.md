# 170 — SSH node

Status: implemented
Created: 2026-09-27

A node that runs a command on another machine over SSH and hands back what it printed. Like the HTTP node ([150](150_streaming.md)), it can stream: each line of output moves on as its own item while the command is still running.

## Config

```toml
module = "PurpleFlow.Nodes.Ssh"

[config]
host = "server.example.com"
port = 22                                    # default 22
user = "deploy"
private_key = "{{ creds.DEPLOY_SSH_KEY }}"   # or: password = "{{ creds.DEPLOY_PASSWORD }}"
host_key = "SHA256:nThbg6kXUpJWGl7E1IGOCspRomTxdCARLviKw6E5SY8"   # optional
command = "tail -n 100 /var/log/app.log"
stdin = "{{ input.text }}"                   # optional
stream = "lines"                             # optional: "lines" or "ndjson"
```

- `host`, `user`, `command`, and one of `password` or `private_key` are required. A workflow missing one fails to load.
- `private_key` is the whole key file, unencrypted: OpenSSH's format (what `ssh-keygen` writes) or the older PEM one (`-----BEGIN RSA PRIVATE KEY-----`). Its line breaks don't matter, so a key pasted into a one-line credential field works. Keys with a passphrase aren't supported.
- With both `password` and `private_key`, the key is tried first.
- `host_key` is the server's key fingerprint, as `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` (or `ssh-keyscan host | ssh-keygen -lf -`) prints it. When set, a server with any other key is refused before anything is sent to it, password included. Without it, any key is accepted. Nothing is read from or written to `~/.ssh`.
- `stdin` is sent to the command's standard input, then closed. Text is sent as is; anything else as JSON. Without `stdin`, standard input is closed right away, so a command that reads it doesn't hang.
- `command` runs in the user's login shell on the server, so templating input into it can run whatever the input says. Pass data through `stdin` instead.

Connecting (including logging in) gives up after 30 seconds. After that, the step's `timeout` applies, which is no limit by default ([120](120_flow.md)). Every execution opens its own connection and closes it when done, or when it's killed or times out.

Uses Erlang's own `:ssh` application; no new dependency.

## Output

```json
{"stdout": "...", "stderr": "...", "exit_status": 0}
```

A non-zero exit status is an error: `exit status 2: <stderr, or stdout if stderr is empty>`. So is a command killed by a signal, a failed login, and a refused host key. No retries. A command that's allowed to fail can say so itself (`grep x file || true`).

## Streaming

With `stream`, the command's standard output is read as it arrives, and each line is handed on right away (`PurpleFlow.Node.emit/2`, [150](150_streaming.md)):

| `stream` | One item per | Item |
|---|---|---|
| `"lines"` | line of text | the line, without its line ending. Blank lines are skipped |
| `"ndjson"` | line of JSON | the decoded line. Blank lines are skipped; a line that isn't JSON fails the execution |

- A last line with no newline is still an item.
- Standard error isn't streamed. It's kept (up to 64 KB) for the error message.
- The node returns `{:ok, []}` when the command exits 0. A non-zero exit is still an error, after the lines already handed on have moved on.
- When a step after it is full and set to wait, the node stops reading, and SSH's own flow control makes the server stop sending: the command blocks on writing once its buffers fill.

`tail -f` with `stream = "lines"` is a workflow that follows a log for as long as it runs. It runs until it's killed, or its step's `timeout`.

The line splitting is shared with the HTTP node, in `PurpleFlow.StreamParser`.

## Tests

Against a real SSH server on localhost (Erlang's `:ssh` daemon, with a test handler instead of a shell):

- a command's stdout, stderr, and exit status; stdin as text and as JSON
- logging in with a password, an OpenSSH ed25519 key with its line breaks turned into spaces, and a PEM RSA key; a wrong password is an error
- a non-zero exit status and a signal are errors
- `host_key`: a matching fingerprint connects, any other is refused
- `stream = "lines"` hands on a line before the command ends, joins lines split across chunks, and keeps a last line with no newline; `"ndjson"` decodes lines; a non-zero exit after streaming is an error
- killing an execution closes its channel on the server
- config mistakes fail at load time
